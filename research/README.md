# Declarus: документы, прогнозы и воспроизводимая оценка

## Что открыть сначала

1. [hypothesis_f1_evaluation.ipynb](hypothesis_f1_evaluation.ipynb) — метрики трёх режимов, сравнение H1 и H2, результаты по шаблонам. Bootstrap-кода в нём нет.
2. [bootstrap_hypotheses_review.ipynb](bootstrap_hypotheses_review.ipynb) — парный bootstrap по документам, доверительные интервалы и проверки чувствительности.

Выводы ячеек сохранены. Для просмотра повторное выполнение не требуется.

## Структура

```text
data/
  images/                  50 PNG синтетических упаковочных листов
  gold/                    50 эталонных JSON с доказательствами и координатами
  ocr/                     50 сохранённых compact OCR JSON
  manifest.json            Идентификаторы, шаблоны, искажения и хеши файлов
predictions/
  ocr_only/                OCR без изображения, без примеров
  ocr_image/               OCR + изображение, без примеров
  ocr_image_3shot/          OCR + изображение, 3 примера
model_evaluation.py         Исходный оценщик, совпадающий с экспериментом
recompute.py                Пересчёт из gold и прогнозов, без API
few_shot_alignment.json     Хеши трёх примеров, промпта и оценщика
reports/
  evaluation.json          Пересчитанные метрики и результаты по документам
  extraction_errors.json   Gold → prediction для ошибочных значений
  bootstrap.json           Пересчитанные интервалы обеих гипотез
  fewshot_comparison.json  Исходный полный отчёт сравнения few-shot
  image_comparison.json    Исходный полный отчёт сравнения изображения
  bootstrap_results.json  Контрольный отчёт прежней bootstrap-проверки
```

В каждом каталоге прогнозов `attempts.json` содержит все 50 статусов, идентификаторы ответов и доступную статистику токенов. Прогнозов 50/49/50 соответственно: исторический `ocr_image/tpl01_005` оборвался на лимите 40 000 выходных токенов. Для него нет валидного prediction; оценщик учитывает попытку как пустое извлечение. Ответ не повторялся. Отсутствующий прогноз не исключается из основного расчёта.

Чтобы проверить конкретный документ, найдите одинаковый идентификатор, например `tpl01_009`, в `data/images`, `data/gold` и каждом каталоге `predictions`. Метрики строятся по значениям, bbox IoU рассматривается отдельно. Полные API-запросы с base64, учётные данные и runtime-история сервиса не включены.

## Локальный пересчёт

Из корня репозитория, Python 3.10+:

```sh
python research/recompute.py
python research/recompute.py --bootstrap
```

Первая команда проверяет хеши изображений, gold, OCR, few-shot, промпта и оценщика, переоценивает прогнозы и сверяет счётчики с исходными отчётами. Вторая дополнительно выполняет 20 000 парных bootstrap-повторов с seed 20261107. Для этих команд достаточно стандартной библиотеки Python; ключи и сеть не нужны.

Для повторного выполнения ноутбуков дополнительно нужны Jupyter, pandas и matplotlib. Запускайте Jupyter из корня клона или из `research/`. Ноутбуки читают локальные отчёты и не вызывают модель.

## Три few-shot примера в приложении

В `../mvp/documents/few-shot_raw/` и `few-shot_labelled/` находятся те же три пары, что использовались в исследовании: исходные пары **2, 4, 5**, записанные как `example1`, `example2`, `example3`. JSON включает исправленные правила единиц. `../mvp/system-prompt/customs-declaration-system-prompt.md` совпадает с зафиксированным промптом. Хеши и соответствие примеров указаны в `few_shot_alignment.json`; дублировать изображения примеров внутри исследования не требуется.

Пайплайн загружает все три пары из этих каталогов автоматически. Это синхронизация входов, а не новый live-тест продукта: воспроизведение сохранённых метрик не требует платных запросов.

## Результаты и границы вывода

- OCR-only: precision **87,39%**, recall **87,72%**, field-level micro-F1 **87,55%**.
- OCR + изображение без примеров: precision **85,07%**, recall **86,09%**, F1 **85,58%**.
- OCR + изображение с тремя примерами: precision **94,68%**, recall **95,67%**, F1 **95,17%**.
- H1: три примера против нуля, **+9,60 п.п.**, 95% ДИ **[+5,73; +13,63] п.п.** Численный критерий положительного эффекта выполнен на этом наборе.
- H2: изображение против OCR-only, **−1,98 п.п.**, 95% ДИ **[−4,50; +0,35] п.п.** Положительный эффект не подтверждён; интервал включает ноль, уверенного ухудшения также не установлено.

В bootstrap повторно выбираются документы, а не поля; micro-F1 каждый раз пересчитывается из суммарных TP/FP/FN. Основной расчёт включает все 50 попыток. Успешные пары и стратификация по шаблонам — дополнительные проверки.

Это синтетические данные шести знакомых шаблонов, три из которых родственны демонстрациям; независимости по семействам форм нет. Результат не доказывает перенос на новые документы заказчика. Запуски OCR-only и с изображением выполнены в разные даты; одинаковый идентификатор модели не фиксирует веса у провайдера. В H2 удалялся только image payload, весь текст запроса сохранялся, включая ссылки на изображения. Синонимы единиц вроде `sqm` и `m2` оценщик не объединяет.

Текущие гипотезы требуют ΔF1 > 0 и нижнюю границу 95% ДИ > 0. Поля `target_pp: 5` в исходном few-shot отчёте — исторический критерий, а не текущий. Исходные отчёты сохранены без редактирования для аудита; их относительные пути описывают старую структуру эксперимента. Для файлов в этом репозитории используйте `data/manifest.json`. Пути к исходным изображениям в нём сокращены до имён файлов; хеш первоначального manifest сохранён отдельно.
