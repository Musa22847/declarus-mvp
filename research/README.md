# Declarus: документы, прогнозы и воспроизводимая оценка

## Что открыть сначала

1. [hypothesis_f1_evaluation.ipynb](hypothesis_f1_evaluation.ipynb) — метрики трёх режимов (тестирования гипотез), сравнение H1 и H2, результаты по шаблонам. 
2. [bootstrap_hypotheses_review.ipynb](bootstrap_hypotheses_review.ipynb) — парный bootstrap по документам, доверительные интервалы и проверки чувствительности.

Выводы ячеек сохранены. Для просмотра повторное выполнение не требуется.

## Структура

```text
data/                      Основные данные
  images/                  50 PNG синтетических упаковочных листов
  gold/                    50 эталонных JSON с доказательствами и координатами
  ocr/                     50 сохранённых compact OCR JSON
  manifest.json            Идентификаторы, шаблоны, искажения и хеши файлов (технический файл)
predictions/               Предсказанные значения 
  ocr_only/                OCR без изображения, без примеров
  ocr_image/               OCR + изображение, без примеров
  ocr_image_3shot/          OCR + изображение, 3 примера
model_evaluation.py         Исходный оценщик, совпадающий с экспериментом
recompute.py                Пересчёт gold и прогнозов (перенесено из ipynb файлов для наглядности)
reports/                   Проверка гипотез
  evaluation.json          Метрики и результаты по документам
  extraction_errors.json   Gold → prediction для ошибочных значений
  bootstrap.json           Пересчитанные интервалы обеих гипотез
  fewshot_comparison.json  Исходный полный отчёт сравнения few-shot
  image_comparison.json    Исходный полный отчёт сравнения изображений
  bootstrap_results.json  Контрольный отчёт прежней bootstrap-проверки
```

В каждом каталоге прогнозов `attempts.json` содержит все 50 статусов, идентификаторы ответов и доступную статистику токенов. Прогнозов 50/49/50 соответственно: один файл `ocr_image/tpl01_005` оборвался на лимите 40 000 выходных токенов. Для него нет валидного prediction; оценщик учитывает попытку как пустое извлечение.

Чтобы проверить конкретный документ, найдите одинаковый идентификатор, например `tpl01_009`, в `data/images`, `data/gold` и каждом каталоге `predictions`. Метрики строятся по значениям. Полные API-запросы с base64, учётные данные и runtime-история сервиса не включены.


## Результаты и границы вывода

- OCR-only: precision **87,39%**, recall **87,72%**, field-level micro-F1 **87,55%**.
- OCR + изображение без примеров: precision **85,07%**, recall **86,09%**, F1 **85,58%**.
- OCR + изображение с тремя примерами: precision **94,68%**, recall **95,67%**, F1 **95,17%**.
- H1: три примера против нуля, **+9,60 п.п.**, 95% ДИ **[+5,73; +13,63] п.п.** Численный критерий положительного эффекта выполнен на этом наборе.
- H2: изображение против OCR-only, **−1,98 п.п.**, 95% ДИ **[−4,50; +0,35] п.п.** Положительный эффект не подтверждён; интервал включает ноль, уверенного ухудшения также не установлено.

В bootstrap повторно выбираются документы, а не поля; micro-F1 каждый раз пересчитывается из суммарных TP/FP/FN.

Это синтетические данные шести знакомых шаблонов, на которых проводилась оценка качества модели.
