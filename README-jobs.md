# Постоянные задания Декларус

Запуск: `docker compose up --build -d`. Запускаются интерфейс `declarus`
и один последовательный `worker`. Python API обработки и формат Excel прежние.

После загрузки файл сразу сохраняется, но запросы к Yandex начинаются только
после «Начать обработку». Ссылка `?job_id=...` открывает то же задание после
обновления страницы; закрытое задание можно открыть также через «Историю».
«Новый документ» не удаляет предыдущие данные. История общая, входа по логину нет.

Постоянная папка `ui/output` содержит результаты и `system-folder`:
`jobs.sqlite3` — состояния/время, `jobs/<job_id>/` — исходники,
`worker.lock` — блокировка второго worker. SQLite-файлы `-wal`/`-shm` служебные.
Не удаляйте их при работающем приложении. Для резервной копии всей папки
сначала остановите оба сервиса. Секреты остаются только в окружении контейнеров.

После перезапуска worker продолжает Qwen по сохранённому ID или формирует Excel
из уже полученного JSON. Прерванный OCR и запрос без сохранённого ID автоматически
не повторяются: в интерфейсе появится ошибка и кнопка ручного повтора.
Если ошибка произошла при экспорте, повтор использует готовый JSON без модели.

Общее время считается от начала обработки без ожидания в очереди и включает
недоступность приложения после перезапуска; это не чистое время вычислений Yandex.
Старые результаты без времени остаются в истории с соответствующей подписью.

Для прямого запуска без Docker нужны два процесса: `streamlit run ui/streamlit_app.py`
и `python ui/worker.py` (worker использует POSIX-блокировку; для Windows используйте Docker).

Проверки без платных API выполняются из корня проекта в отдельном контейнере:

```sh
docker run --rm --network none --entrypoint python \
  -e PYTHONPATH=/app/ui:/app/mvp -v "$PWD/tests:/tests:ro" \
  declarus-mvp:0.2.0 -m unittest discover -s /tests -v
```

Тесты сами создают временные папки; секреты и рабочая история не подключаются.
